# 寄丢日记：面试讲解

## 一分钟介绍

我做的是一个 Flutter 离线日记项目，主要场景是记录每天的经历和心情。它包括日记新增、编辑、详情查看、删除和搜索，也可以按日期、心情筛选。首页展示本周真实的心情记录，我的页面展示日记数量、心情分布，并支持深色模式。

实现上，我用 Provider 和 ChangeNotifier 管理跨页面共享的日记与心情数据，用 SharedPreferences 保存 JSON 快照。编辑页保存成功后，列表、首页和统计页通过通知自动更新。底部导航用 IndexedStack 保留页面状态，详情和编辑使用 Navigator。

我先搭建了基础页面，后续通过 AI 协助完成了数据层和功能。我需要能解释并验证这些实现，而不会把辅助生成的代码说成全部由自己独立完成。

## 常见追问

### 为什么用状态管理？

写日记影响列表、首页计数和统计，多个页面需要同一份数据。把数据放在 DiaryStore 中，页面通过 context.watch 订阅变化，操作时通过 context.read 调用保存方法。ChangeNotifier 的 notifyListeners 让订阅页面重建。输入框、搜索条件等局部状态仍用 setState。

### 一次保存发生了什么？

编辑页先验证正文非空，再构造 DiaryEntry。新记录创建 ID，编辑保留原 ID。Store 生成候选数据快照，用 JSON 编码后调用本地存储。成功后更新内存并通知订阅者，再关闭编辑页。失败则保留旧数据和用户输入，并提示重试。busy 状态避免重叠写入，但这不等同于数据库事务或系统级持久性保证。

### 本地存储怎么做？为什么没有 SQLite？

当前使用 SharedPreferences 存储一个带版本号的 JSON 字符串。数据包含日记列表、日期与心情映射、深色模式设置，启动时反序列化恢复。它便于完成小规模学习项目，但每次修改都重写整个快照，大量长文本时效率和可靠性不合适。更正式的版本应使用数据库，让日记和心情各自有表，用事务管理相关更新。

### 心情和日记是什么关系？

日记记录包含自己的心情，同一天允许多篇。每日心情是独立的日期映射，每天只保留一个，保存日记会更新对应日期的心情。删除日记后，当天的心情打卡仍保留。后来单独改每日心情，不会修改旧日记里的心情。

### 路由怎么用？

底部导航通过 IndexedStack 切换主页面，可以保留搜索筛选状态。进入详情和编辑页面通过 Navigator.push 和 MaterialPageRoute；保存后 Navigator.pop。共享 Provider 位于 MaterialApp 上层，所以新路由也能访问同一个 Store。详情根据 ID 查最新数据，修改返回后不会继续展示旧对象。

### 怎么处理异常和误操作？

空正文不允许保存，保存时禁用重复点击；退出有修改的编辑页通过 PopScope 提醒；单篇删除需要确认。如果读取的数据格式错误或版本不支持，保留原始存储并禁止后续覆盖。保存异常时不关闭编辑页，用户输入还在。

### 搜索怎么实现？

在内存列表上用 where 过滤，标题和正文统一转小写匹配关键词，再组合心情、日期条件。适合小规模列表。记录多时应迁移到数据库查询、分页，必要时增加全文索引。

### 每日一想是否用了 Dio？

当前按日期轮换内置题库，不进行网络请求，所以没有使用 Dio。未来接在线题库或云同步才需要网络层，并处理超时、错误和缓存。面试时不要把 Dio 写成此项目已实现的技术。

### 做了什么测试？

测试覆盖日记新增、编辑、搜索、详情查看、删除，本地快照恢复、同日心情覆盖、统计和备份结构，损坏数据保留，以及小屏幕布局和未保存退出确认。存储测试采用 SharedPreferences 的模拟存储，不能替代 Android 真机上的系统落盘和生命周期测试。

## 面试前亲自练习

1. 写两篇不同日期的日记，修改其中一篇，再搜索和删除。
2. 同一天更换心情，确认统计只增加一天；重启应用确认记录恢复。
3. 从编辑页的 _save 跟到 DiaryStore.saveEntry 和 _commit，说明数据流。
4. 解释 context.watch 与 context.read，说明为什么首页会更新。
5. 亲自修改一个小功能，例如新增一种心情，并运行测试。

## 当前限制与改进方向

没有云同步、账号系统、自动草稿、附件、加密或备份导入。复制 JSON 只是手动备份能力。下一步优先迁移数据库并加入备份恢复，再根据实际需求增加草稿和同步；不要把计划说成完成的功能。
